# `/edit-picture` 的「擴散細化層」(`detail`):只重畫一小塊的細節,再用羽化蓋回去(規劃,還沒開始做)

> 2026-10-24,使用者提出。**這份是規劃,不是實作。** 成品放在 `/edit-picture`(DESIGN.edit-picture.md)裡,多一種圖層與一個啟用項「啟用擴散編修」。

## 1. 為什麼要做
本機小模型 SDXS 步數很少(一到兩步的蒸餾模型),整張圖看起來會糊成一片。想要細節時,不是整張重畫,而是**只針對一小塊**(臉、手、招牌、某個物件)放大、重畫、再蓋回去。

## 2. 做法
1. **決定區域(程式先讀,模型不給座標)**:來源依序是——使用者在圖上框選或塗抹的;已選取的圖層或物件(`/edit-game` 的焦點的同一種概念);說的話指到的物件(「臉」「招牌」)由視覺模型回傳框,程式驗證並收進圖內。
2. **細化生成**:裁出區域,**四周多裁一圈**當脈絡(區域太小時模型看不到周圍,容易把臉畫成別人),放大到模型熟悉的解析度,用「圖的內容描述 ＋ 區域專屬描述」當提示詞,以原裁片當起點重畫一次(img2img),強度低,保留構圖只補細節。
3. **蓋回去**:結果縮回原尺寸,用**羽化遮罩**混合;混合前先做**色調與亮度對齊**(否則會出現色塊邊界)。羽化寬度約區域邊長的 5%～10%,可調。
4. **分層保存**:每個細化結果是一個獨立圖層,不滿意就隱藏、刪除、換 seed 重畫,不影響其他層;原圖永遠不動。

## 3. 新的圖層型別 `detail`(在 `edit_picture_core.js`,`FaEditPicture`)
```
detail { region:{x,y,w,h} | marks:[…], target:'all'|<物件 id>, prompt, strength, feather, context(多裁一圈的比例),
         seed, model:'sdxs'|'sd15'|'sd3'|'online', result:<圖片 id>, opacity, blend }
```
- 跟 `heal`(修復層)同一種:有 `marks`／`region`、可隱藏、可調透明度、可復原;合成時對下方的合成結果作用。
- 動作加進封閉集合:`add_detail{of,at,r,prompt,strength}`(位置用 `of／at`,對圖片物件的框算,同 `add_heal`)、`set_detail{id,prompt,strength,feather,seed}`、`redo_detail{id}`(換 seed 重畫)。宿主執行的:`generate_detail`(叫生圖模型)。
- 程式先讀:「把臉細化」「讓招牌的字更清楚」「這裡再清楚一點」(焦點)→ 先判斷是不是細化(關鍵詞),再決定區域;讀不懂的才叫模型,模型只准回上面的動作。

## 4. UI(跟修復畫筆同一個位置)
- 工具列新增 **✨ 擴散細化**,進入後在圖上框選或塗抹要細化的區域。
- 右側屬性面板多一組:提示詞(預設由視覺模型讀這塊內容,可編輯)、強度、羽化寬度、脈絡(多裁多少)、模型、**重畫(換 seed)**、**套用／取消**。
- 生成中顯示進度;完成後先以**預覽疊層**顯示(原圖／細化前後對照可切換),按「接受」才變成正式圖層。
- **啟用項**:設定裡「啟用擴散編修」(預設關)。沒啟用或沒有生圖模型(沒下載本機模型、也沒線上金鑰)時,按鈕灰掉並說明原因;跟 `repaint`(用 AI 重畫整張)共用同一個模型設定,不重複設定。
- 選取方式與 §edit-game 的「focus／select」同一套:可以進入也可以離開,誤觸不逼人點一個。

## 5. 模型選擇(要先實測的核心問題)
- **SDXS 的 img2img 在低強度下能不能只補細節而不改構圖?** 蒸餾的一到兩步模型,「強度」行為跟一般 SD 不一樣,可能一重畫整塊都變掉。這決定 `model` 欄位的預設。
- 替代:區域放大用傳統方法(Lanczos),再用步數多的模型(SD1.5／SD3,或線上 NVIDIA)只在這個小區域跑 20 步左右。這也是 `detail` 把 `model` 留成欄位的原因。
- 最小驗證(**實作前先做**):在 Electron 裡拿一張 SDXS 的圖,固定一個區域跑一次「裁切 → 重畫 → 羽化蓋回」,對比原圖有沒有更清楚、邊界有沒有接縫。結果決定走哪個模型。

## 6. 實作位置與重用
| 用途 | 現成 |
|---|---|
| 圖層、合成、區域標記、復原 | `edit/edit_picture_core.js`、`edit_picture_ui.js`、`pic_fx.js`(修復層的區域與畫筆) |
| 縮放、羽化、色調統計 | `imgproc/imgproc_core.js`(面積平均縮放)、`pic_fx.js`;羽化遮罩與色調對齊是新寫的純函式 |
| 生圖 | `_generateImage`(線上 NVIDIA、本機 SDXS／SD1.5／SD3,見 DESIGN.image-generation.md) |
| 視覺模型讀區域內容 | `_visionDescribe`(同 repaint) |
| 外框、物件欄、復原重做 | `edit/edit_shell.js` |
新增(預計):`edit/pic_detail.js`(純函式:取框、放大裁片、羽化遮罩、色調對齊、蓋回去;可以在 Node 測)。

## 7. 驗證
- **單元測試(Node)**:羽化遮罩(邊緣 0 → 中心 1、單調)、色調對齊(平均與標準差對齊後差距變小)、區域與脈絡的換算(收進圖內、不超出邊界)、`detail` 層的合成與復原、動作驗證與程式先讀的指令。
- **Electron 評測**:用**假的生圖模型**回傳固定圖,驗證圖層出現、蓋回去的邊界像素差在門檻內(沒有接縫)、隱藏圖層後畫面回到原樣、專案存進 IndexedDB 後重新掛載仍在。
- **無法自動驗證**:真實模型細化的品質(要使用者實際看)、視覺模型框得準不準。

## 8. 風險與限制
- 品質取決於模型;SDXS 可能不適合 img2img(§5),要實測後才能承諾效果。
- 區域太小或脈絡不夠,會畫成別的東西;區域之間重疊時,後做的蓋掉先做的(順序固定)。
- 大圖(>1600 px)已經會被縮小保存;細化層的結果以區域為單位存,不再存整張。
- 沒有啟用或沒有模型時整個功能不可用,要說清楚原因,不是默默失敗。

## 9. 要先問使用者的事(給建議的預設)
1. 區域怎麼選:建議第一版**只做「你框選／塗抹」**,語言指到的物件(視覺模型回框)放第二版。
2. 預設模型:建議先做 §5 的最小驗證,再決定;驗證前預設 SDXS,保留 `model` 欄位。
3. 結果要不要先預覽再接受:建議**要**(預設),可關。
