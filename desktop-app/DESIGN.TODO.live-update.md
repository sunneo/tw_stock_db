# 熱更新（live-update）還沒做的事

已完成的設計與鐵則在 `.claude/skills/publish-live-update-patch/SKILL.md`（兩份 manifest、凍結的互換版 v188、`main-ext.js` 自己接手更新／模組覆蓋／缺模組補回）。這裡只放還沒做的。

## 發佈腳本
- `scripts/publish.sh` 結尾的驗證只看 `manifest.json`（互換版，凍結在 188），所以每次會印「版本 188，檢查碼都對」。要改成驗證 `manifest.v2.json` 的版本與每個檔案（含 `v2/` 底下的路徑與分段），而且用**固定 commit 的網址**讀（分支網址被下載端快取，新版本幾分鐘內可能還是舊的）。
- 發佈後自動等到下載端也換成新版本再回報完成（或明講「下載端還沒同步」）。

## 更新處理（main-ext.js）
- `live-patch` 的 state.json 跟實際檔案對不上時自動重建（現在只是退回內建版本）。目前沒有實際發生的證據，先記著。
- 更新處理的行為（分檔下載、固定 commit、缺模組補回）只有測試版模擬過；Linux AppImage 與 macOS 沒有逐一驗證（Linux 使用者回報電腦操作可以用）。

## 其他
- `main.js`（入口）的修正（模組名單從清單自動取得、單檔不設上限、分檔下載）只對新安裝生效；舊安裝由 `main-ext.js` 接手，不需要重新安裝。
- 凍結的互換版不再更新（使用者指示）。如果哪天互換版本身有嚴重錯誤才需要重新凍結，步驟見技能文件。
