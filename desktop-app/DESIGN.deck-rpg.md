# 簡報的 RPG 式對話場景（人物走路、頭像對話框、過場、劇情畫面）

目標：用簡報本身的物件設計，做出像 RPG／視覺小說那樣的場景——人物在地圖上走路、轉向、對話，下方冒出頭像對話框，說話的人變亮、對話框閃動；
走進屋外、走到桃花樹下，畫面暗下來，切到大張的劇情畫面加字幕。例子是「桃園三結義」。所有功能也要能走 CoLU（弱模型不用自己寫 YAML）。

## 決定：不另做一種視覺，擴充 collage 的物件設計
collage 本來就有：項目的位置、出現時間、keys 移動、say 台詞、scenes 場景、camera 鏡頭、texts 敘事字、sounds 音效、都跟旁白的「第 N 句」對齊。
RPG 需要的只是幾種「不需要圖檔的圖」與幾個通用欄位，所以放進 collage，不另開 `kind: rpg`：舊簡報完全不受影響，所有簡報功能（匯出、驗證、音效、CoLU）自然共用。

## 格式（都是 collage 的欄位）
| 欄位 | 意思 |
|---|---|
| `src: map:<名>` | 像素地圖，鋪滿舞台，16×9 格：`house_interior` 屋內、`village` 村莊、`peach_orchard` 桃園 |
| `src: actor:<外觀>` | 像素小人，4 個方向、走路兩步。外觀＝預設名稱（liu_bei guan_yu zhang_fei mother villager_m villager_f elder soldier child）或 `look` 自訂 |
| `src: bust:<外觀>` | 半身像（向量，眨眼、說話時嘴巴開合），大張劇情畫面用 |
| `src: cg:<名>` / `fx:petals` | 大張畫面背景（`peach_oath` 桃園黃昏、`dusk_hall` 暮色大廳）／飄落的花瓣 |
| `look` | `{skin fair\|tan\|dark\|red, hair black\|gray\|brown\|white, hairStyle topknot\|long\|short\|bun\|wild, beard none\|short\|long\|bushy, robe green\|red\|blue\|black\|brown\|gray\|yellow\|white, head none\|headband\|hat}` |
| `tx` `ty` `tw` | 地圖格子座標（人物站在格子底邊中央）與寬度（格）；`keys` 裡也能寫 `tx` `ty`＝走過去 |
| `anchor` `face` | 座標指的是圖的哪一點（feet／center／topleft）；起始朝向。移動時自動轉向、換腳；`keys` 裡的 `face` 讓站著的人轉身 |
| `name` | 對話框上的名字（`label` 是圖下面的名牌，不同） |
| `say[].style` | `bubble`（預設，泡泡）／`box`（RPG 對話框：頭像、名牌、逐字打出、閃爍的 ▼、剛出現時閃動）／`subtitle`（電影字幕） |
| `spotlight`（整個 collage） | 有人用 box／subtitle 說話時，說話的人變亮（頭上 ▼ 標記、說話時嘴巴動），其他人變暗 |
| `scenes[].effect: black` | 舊場景暗下去、新場景從黑暗中出現（同一頁換地圖） |
| `curtain` | 蓋在舞台上的黑幕，`alpha` 1＝全黑（結尾「暗下來」） |
| `fullscreen`（整個 collage） | 舞台鋪滿整張投影片（需要 layout visual） |
| `sheet` `portrait` | 使用者素材：精靈圖（`{cols, rows, dirs?, idle?, fps?}`，每一排一個方向，欄是走路循環）與頭像（對話框用它代替畫的半身像） |
| `id` `voice` | 項目代號（觸發條件、`say.id` 之外的參照用）；人物的「嘴音」：`calm\|deep\|rough\|elder\|old_woman\|young\|child\|narrator\|none` 或數字 `{pitch, wave, jitter, vibrato, noise, len, rate, vol}`；畫出來的人物有預設嘴音。每打出一個字一個 `blip` 音效（跳過空白與標點，確定性，不用 TTS） |
| `say[].id` `say[].at` | 對白有自己的時間軸：`at` 可以是秒、`{sentence, edge: start\|end, offset}`（等旁白第 N 句）或 `{line: "l1", edge: end, offset}`（接在另一句對白後面）；長度＝綁定的句長、`sec`、或依字數估（`max(1.4, 0.7+字數×0.125)`）；整頁長度延長到最後一句對白與走路結束。所以旁白可以講一個故事（或不要旁白），然後人物用自己的聲音說話 |
| `states` `auto` `keys[].state/src/hold` `triggers` | 「一組移動時的動畫影格」與「到哪邊換什麼圖／狀態」：`states: {walk: {frames: [0,1,2,3], fps: 6}, idle: {frames: [1]}, bow: {src, sheet, frames, loop: false}, nod: {pose: bow}}`（影格列表＝面向方向那一排的欄；`facing: false` 則逐列編號；影格也可以是圖片代號；`pose`＝畫出來的人物鞠躬／跳／抖／驚訝）；`auto: {moving: walk, still: idle}` 依是否在移動切狀態；`keys` 在某時間切狀態（`hold` 秒後回去）或換圖；`triggers: [{when: {tile: [x,y]} \| {near: [x,y], r, item}, state\|src, hold}]` 站到某格／靠近某處（或某個 `id` 的項目靠近）就切換——例如有人走近門，門換成打開的圖 |
| `depth`（整個 collage） | `y`：地圖的物件（樹、房子、桌子…）與放在格子上的圖（人物、精靈）依「腳底的列」一起排序畫——人物走到樹後面會被擋住、走到前面會擋住樹。沒寫就跟以前一樣（人物永遠在地圖上面）。排程器產生的故事預設 `depth: y` |
| `tz` `shadow` `parallax` | `tz`＝離地高度（格，也能寫在 `keys` 裡做跳躍：`{at, sec, tz: 1.5}` 再 `{at, sec, tz: 0}`），腳下的影子留在地上、越高越小越淡；`shadow` true／false＝格子上圖片的柔和影子（預設：人物在 `depth: y` 或有高度時開）；`parallax` 0..1＝鏡頭移動時跟著世界動的比例（1 預設，0＝釘在畫面上的遠景） |
程式：`renderer/src/deck/rpg_art.js`（程序化圖片、頭像對話框、字幕、A*）、`deck_core.js`（格式驗證與繪製、狀態／觸發、時間錨點）、`deck_sfx.js`（`blip` 嘴音合成）、`deck_player.js`（載入 `portrait`、狀態用到的額外圖片 `extra`；嘴音快取鍵含聲音參數）、`deck_tools.js`（給模型的格式說明、素材代號不解析）、`sprite_pixel.js`（單一物件的點陣精靈，見 DESIGN.deck-assets.md）。

## 走路：繞路演算法
每張地圖有「障礙格」（房子、樹、井、桌子、床、牆）與一組具名錨點（door、tree、center…）。`findPath(map, from, to)` 是 4 方向 A*，回傳轉彎點；
目標落在牆或物件上就走到它前面（南側優先）；規劃器把路線變成 `keys`（每個轉彎點一個 tx／ty，依距離算秒數，路徑太長時最多加快一倍，讓走路在旁白那一句內結束）。

## CoLU：故事 → 舞台（rpg_plan.js）
程式讀、程式排、程式檢查；歧義才問封閉問題，附預設：
1. 讀：一行一個事件——「名字：「台詞」」「【暗下來】」「（走向桃花樹）」或敘述句；認得人物（劉備／玄德…）與地點（屋內／村莊／桃園…）。
2. 排：每一拍＝一句旁白（第 N 句就是第 N 拍，用簡報的 splitSentences 驗證）；人物在場景開始時就站好（進場的人在他那一拍走進來）；說話的人離對方太遠就先走近；
   雙方轉身面對面；換地點＝先走到門口、過黑幕、進新地圖；走向桃花樹＝過場後在桃園走到樹下；大張畫面＝半身像並排加字幕；結尾黑幕。
3. 問：地點認不出來（預設村莊）、同一個人物有好幾個素材都符合（預設第一個）；用 `answers` 帶回答案再排一次。未知說話者（「老漢說：「…」」）依名字選外觀（老→老者、婦→村婦…）。
4. 查：排出來的 collage 用 deck_core 的 validate 檢查；旁白句數要等於拍數。
素材：`assets: [{id, src, use}]`，`use` 是使用者對素材用途的描述（「劉備走路 4x4 精靈圖」「劉備頭像」「桃園的地圖」）；描述裡有人物名字加「走路／頭像／地圖」就配對上（格數從描述的 `4x4` 讀）；沒有對得上的就用程式畫的。
桌面版入口：`_deckRpgRecipe`（接在 `_deckStoryRecipe` 前面；故事有對話，或點名 RPG／頭像／地圖／人物走路／對話框，或是「桃園三結義」）。附上的圖片＋任務裡提到它的那一句＝素材。

### 口語描述 → 動作（`describeToScript`）
使用者不一定寫腳本：「在屋內劉備跟他母親對話，出來屋外到村莊跟張飛、關羽對話，三個人走向桃花樹下，暗下來切到下一張 scene，這個 scene 是劉關張三人桃園三結義的劇情畫面，大張的，有三個人說話的字幕，不求同月同日生，但求同月同日死」。
程式先把它轉成上面那種腳本（`【屋內】` `劉備：「…」` `（三個人走向桃花樹下）` `【暗下來】` `【劇情畫面】`），再排舞台：認人物（含簡稱「劉關張」、「他母親」、「三個人」）、認地點、認走向／暗下來／劇情畫面／字幕。
- 沒給台詞的對話：內建故事（桃園三結義）有現成台詞；沒有就留下「空位」（`needs`），桌面版由 AI 用嚴格格式 `名字：台詞` 補（`_rpgWriteLines`，驗證、重試一次、60 秒逾時、失敗退回樣板台詞並在 `notes` 說明）。
- 輸出 `understood`（它聽懂了什麼）與 `script`（它轉出來的腳本），讓使用者檢查。
- 旁白只有開頭的敘述；中間的「走向…」變成畫面上的文字；對白用 `say.at.line` 一句接一句，各自有嘴音。

## 已知限制（誠實）
- 地圖物件（樹、房子）跟人物沒有前後遮擋：人物永遠畫在地圖上面；路線避開物件，但不會「走到樹後面被擋住」。
- 對話框蓋住畫面下方約 30%：規劃器讓對話場景的人站在第 5 排以上；手寫時要自己注意。
- 旁白（TTS）只有一個聲音；人物的聲音是「嘴音」（像 RPG 的說話音，不是真人聲），每個人物不同。
- 走路的時間用字數估旁白長度（真正的語音長度要語音產生後才知道），所以很長的路徑可能比那一句長，這時場景切換會把它切掉（黑幕蓋住）。
- 沒驗證：`portrait`／精靈圖在簡報封包（deck_pack）、PPTX 匯出、MP4 匯出裡的處理（匯出用同一個 draw，但封包有沒有帶上頭像圖沒測）；真實模型用這份格式說明直接寫 YAML 的成功率。
- 3 張地圖、2 個大張背景、9 個外觀預設；人物只有 4 個方向（沒有斜向）。

## 素材製作工具（使用者提的方向；階段 1a 已做，其餘還沒）
使用者可以自己給素材並描述用途（已支援，見上）；也希望全程交給 AI 做：
1. **點陣圖物件設計工具**：AI 用封閉的小工具（調色盤、格子、形狀、鏡像、描邊）畫出人物／物件／地磚，每一步由程式檢查。
2. **3D 建模 → 2D 截圖 → 點陣化 → 多個動作畫格 → 精靈圖**：用現有的 3D 場景（scene3d／viewer3d）建人物，從 4 個方向、走路循環的幾個姿勢截圖，縮小並量化成調色盤，排成 `sheet`。
   渲染風格三種：真實、動漫（賽璐珞上色＋描邊）、可愛卡通（圓、粗輪廓）。這條需要：人物骨架與走路姿勢的描述、無頭渲染（Electron 離屏）、描邊／量化、輸出成素材目錄的圖片。
3. 素材目錄：每個素材帶「用途」描述，規劃器配對時用（已有雛形：`assets[].use`）。
第 1、3 項只做了「單一靜態物件」（`make_object_sprite`：樹、松、房子、桌子、箱子、石頭、井，見 DESIGN.deck-assets.md）；人物精靈圖、點陣圖物件設計工具、風格（真實／動漫／可愛）尚未實作。

## 2.5D（除了 2D，還能做斜視／等角／有景深的舞台）
可以，而且大半的材料現成：座標已經是**地圖格子**（`tx` `ty`），人物是**以腳底為錨點的貼圖**（精靈圖或程式畫的），地圖是**程式畫的格子**（不是一張死圖）。2.5D 是「把同一份格子描述換一種投影畫出來」，不是另一個格式。分三階，由便宜到貴：

1. **景深排序＋高度＋影子——已實作（2026-10）**：舞台 `depth: y`（地圖物件與格子上的圖依腳底列排序，`rpg_art.mapObjects` 給每個物件的底邊列；果園的花瓣是最後一個）、項目 `tz`（含 keys 的跳躍）與影子、`parallax`。
   實作：`drawCollage` 把每個項目的畫法包成 `runItem(k, part)`；`depth: y` 時先畫每張地圖的地面（`part: 'ground'`），再把「地圖物件＋格子上的圖」依腳底列（同列再依 z、順序）排序一個一個畫；多個場景時只畫看得到的那張地圖的物件。
   限制：`depth: y` 時，其他不在格子上的項目（飛出來的字、特效）畫在整層之上；一張圖只有一個腳底列（寬的圖不會「一半在樹前一半在樹後」）；`parallax` 只動圖片本身，不動名牌與泡泡。
2. **等角（isometric）檢視**：舞台 `view: iso`（預設 `top`＝現在的 3/4 俯視）。同一份地圖格子，地面畫成菱形，物件畫成有厚度的方塊（用 3D 基本幾何：box／cylinder／cone，跟 `render_3d_scene` 同一套）；
   人物仍是貼圖（billboard），站在投影後的位置，依 (tx+ty) 由遠到近排序；`camera` 可以有 `yaw`（90° 一格地轉）。走路的方向在畫面上是斜的，所以人物需要**斜向的朝向**：
   程式畫的人物本來只有 4 個方向；用「3D 人物→精靈圖」（見 DESIGN.deck-assets.md）時任何角度都能轉出來，所以直接做 **8 個方向**（`dirs` 擴成 8 個，`face` 多 `up_left` `up_right` `down_left` `down_right`）。使用者自己的 4 方向精靈圖在等角檢視時取最近的方向，並在說明裡講清楚。
3. **真正的 3D 舞台＋貼圖人物**：用現有的 3D 舞台（`deck_stage3d`，有 CPU 後備）當世界、人物當面向鏡頭的平面；鏡頭可以環繞、推拉。這一階要處理的是 3D 場景與貼圖的混排排序、CPU 後備的速度與畫質，成本最高，**等前兩階有成品、確定需要再做**。

規劃器（口語描述→動作）不用改：它輸出的是格子座標與動作，投影只是 `view` 的設定；`view: iso` 時 A* 仍然在格子上算，路線不變。
限制：等角的地圖樣板要另外畫（現在 3 張地圖是俯視樣式）；2.5D 的人物近景頭像不受影響（頭像是另一張圖）。
