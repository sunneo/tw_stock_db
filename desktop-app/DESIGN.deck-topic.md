# 主題簡報：`/media-presentation` 只給主題時，程式自己組

> 2026-10-23。起因：使用者下了
> 「/media-presentation 用幼兒教育的方式，介紹飛機怎麼飛，要圖文並茂……可以上網找照片……繁體中文，語速1.0」，
> 子 agent 失敗：「子agent重試了 3 次，仍然沒有真正產生簡報……可以換較強的模型」。
> 使用者的要求：**不接受它犯錯然後放棄**；它也**沒有向使用者申請延伸回合（也沒申請工具）**。

---

## 一、從那份記錄看到的失敗原因（逐項對照程式）

| # | 現象（記錄） | 根因 |
| --- | --- | --- |
| 1 | 要找網路照片，卻只有 `import_image_url`（要「直接的圖片網址」）；模型想了很久不知道網址從哪來，轉去 `cute_picture`（只有 20 種固定物件，沒有飛機），最後放棄真照片 | 領域工具裡**沒有「找照片」的工具**（沒有搜尋圖片的路）。瀏覽器工具需要使用者裝擴充功能，而且要模型自己操作搜尋頁、抓網址 |
| 2 | `get_presentation_topic` 連錯三次：`{names:[…]}`、空的 `topic` | 工具只收 `topic`；弱模型寫成陣列或沒寫，回錯誤再繞一圈 |
| 3 | 把 `list_uploaded_files()` 當成最終回覆；把整份 JSON 當最後的文字 | 弱模型不會自己完成「呼叫 render_presentation」這件事 |
| 4 | `render_presentation` 的 yaml 一直寫錯（缺 `deck:`、`visual` 寫成字串、`type` 該是 `kind`、`@img1` 根本沒匯入過） | 讓模型**一次寫完整份 yaml**，格式細節太多 |
| 5 | 「子agent說做完了但沒產生簡報——自動重來」三次，每次都是同一個模型從頭再寫 | 重來＝同樣的冷啟動、同樣的錯；沒有換做法 |
| 6 | 最後訊息「可以換較強的模型」 | 違反既定原則（不靠換模型復原，見記憶 no_model_switching）；而且沒有任何具體原因 |
| 7 | 沒有申請延伸回合、沒有申請工具（`request_additional_tools`、`extend_rounds`） | 這兩個機制都存在，但要模型自己想到才會用；弱模型不會。回合沒用完就停了，程式端的「回合用完才代為提出」也不會觸發 |

## 二、做法（UML design 的精神：細切成封閉的小步驟，每一步有退路）

`/media-presentation` 照舊先讓子 agent（模型）試一次——它能做互動小遊戲、3D、附件圖片等程式做不到的事。**只要它沒有真的做出簡報，而任務沒有檔案或網址（只給主題），就不再叫同一個模型從頭再寫，改由程式自己組**（`_deckTopicRecipe`，核心在 `renderer/src/deck/deck_topic.js`）：

```
需求 → ① 解析（程式）：幼兒風？要找照片？語言、語速、聲音
     → ② 規劃（模型，一個封閉問題）：每行一頁「標題｜重點｜找照片的英文關鍵字」；格式不對／模型沒回應 → 樣板
     → ③ 旁白（模型，每頁一個封閉小問題，3 頁一組並行）：格式不合 → 用重點當旁白；模型整個不通 → 不再問
     → ④ 找照片（程式）：每頁 find_photo；找不到換更短的關鍵字再試一次；還是沒有 → 這頁不放圖
     → ⑤ 寫 yaml（程式）：deck 對應、章節、每頁標題／條列／旁白／圖，圖用 kind（幼兒風 collage、一般 image）
     → ⑥ 驗證（render_presentation）：回報問題 → 只修有問題的那一頁（拿掉壞的圖、截短太長的字）；第 4 輪還不行就去掉所有圖，保證做得出來
```

### 樣板（沒有模型時的最後一條路）
把需求句拆成子句（`，。；、`、「像是」「例如」「為例」），丟掉說明用的句子（繁體中文、語速、圖文並茂…），**一個子句一頁**；第一頁封面、最後一頁總結；找照片的關鍵字查表（機場、北海道、雲層、平流層、華航、行李…），表裡沒有再用圖像分流的名詞表補。使用者點名的每一件事都會有一頁。實測：**完全沒有模型**時，那個飛機的需求也做出 12 頁、10 張真照片的簡報。

### 找照片（`find_photo`，`_deckFindPhoto`）
自己搜尋、不靠模型猜網址：Wikimedia Commons（先）→ Openverse（備援），都是免費授權、不需要金鑰、允許瀏覽器直接連線（網頁版與桌面版共用）。結果依「標題裡有幾個關鍵字」排序，下載後檢查是圖片、夠大、不是壞圖，匯入成這次簡報的 `@imgN`，並回報**出處與授權**（組簡報時寫進該頁的備註）。同時加進簡報領域的工具清單，並在子 agent 的系統提示裡寫明「要真實照片先用 find_photo，不要自己寫網址；找不到貼題的而瀏覽器有連線，可以自己用瀏覽器工具找（再用 import_image_url 匯入）；都不行才換關鍵字一次、再不行自己畫，不要因為一張圖放棄整份簡報」。（實測：遠端那台 gpt-oss:120b 自己就會想到用 browser action 找照片，強的模型這條路走得通，所以提示不禁止它。）

### 其他補強
- `get_presentation_topic` 接受 `names`／`topics` 陣列、或什麼都沒給（回 `format`），不再丟錯誤讓弱模型繞圈。
- 子 agent 的冷重試從 2 次降成 1 次（程式組簡報之後才輪到），失敗訊息**不再叫使用者換模型**，改成具體說明：模型寫的簡報沒通過檢查或沒呼叫 `render_presentation`、程式自己組也沒成功的原因，並提示補一句要講哪幾件事或附上素材。
- 全程每一步都寫進進度卡片的記錄（規劃用了模型還是樣板、每頁找到什麼照片與授權、驗證回報了什麼、修了什麼）。

## 三、關於「延伸回合」與「申請工具」

這個流程**不靠模型自己申請**：缺的工具（找照片）直接補進領域；程式組簡報不吃回合。原有的 `extend_rounds`（回合用完還在做時，程式代為提出、使用者決定）與 `request_additional_tools` 仍保留給需要長時間探索的子任務。

## 四、測試

- `node scripts/deck-tests/deck_topic.test.js`（18 項）：需求解析（幼兒、照片、語言、語速、聲音）、規劃格式與容錯、樣板（那個飛機的需求每件事都有一頁、關鍵字、說明句不成頁）、旁白驗收、組簡報（deck 對應、kind、出處備註、條列長度）、修復只動出問題的頁。
- 真實 Electron：`find_photo` 真的連到 Wikimedia Commons 並匯入；完全沒有模型時的整條流程（12 頁、10 張照片、render 通過）；子 agent 失敗＋假規劃模型時，`/media-presentation` 由程式組出簡報並顯示播放器。

## 五、還沒做／沒驗證

- 照片的**相關度**只靠關鍵字與標題比對（例如「平流層」曾搜到同名的賭場塔，已改關鍵字，但不保證每張都對）；沒有請視覺模型逐張確認。
- 只涵蓋「只給主題」；有附件、網址、檔案夾、pptx 的任務仍走原本的子 agent 與食譜。
- 樣板的子句拆分是規則式的，句型很特別的需求可能拆得不漂亮（模型可用時由模型規劃）。
- 旁白的語氣（幼兒風）只靠提示詞，沒有逐句檢查用詞難度。
- 沒有把「程式組簡報」的做法餵回離線訓練器（與 `/image` 一樣的後續工作）。
