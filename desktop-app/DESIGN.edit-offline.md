# 編輯器的離線 AI 支援（/edit-svg、/edit-picture、/edit-3d-model、/edit-media-presentation、/edit-game-2d、/edit-game-3d）

> 2026-10-25。核心 `renderer/src/edit/edit_offline.js`（`FaEditOffline`，純函式 UMD，測試 `scripts/edit-tests/edit_offline.test.js`）；宿主端在 `edit_host.js` 的 `_edOfflineTry`，六個編輯器的 `ask` 函式各插一行。

## 為什麼不能直接叫小模型寫 JSON
原本每個編輯器的 AI 路徑是：把整份說明與場景丟給模型，要它一次吐出一串 JSON 動作。大模型做得到；0.6B～4B 的離線小模型會漏欄位、編動作名、放錯位置（實測過線上模型都會把濾鏡層加上不該有的位置參數）。

## 分工（跟 DESIGN.colu.md、DESIGN.offline-plans.md 同一個形狀）
- **程式**：切子句 → 讀出「顏色、數字、倍數、方向、相對位置（右邊／上面…）、形狀、引號裡的字」→ 找物件（名字比對，顏色一致加分）→ 判斷意圖 → 用各編輯器的封閉動作組出編輯。
- **模型**：只在程式判斷不了時被問**一個字母選擇題**（`letterPrompt`／`parseLetter`）：「這句話是要做哪一件事？」「說的是哪一個物件？」。答不出來（逾時、亂答）就用程式的預設，或把那句話列為「看不懂」，不會亂改。
- **最後一道檢查**：組出的動作仍然由各核心的 `applyEdits` 檢查，所以模型答錯也不會弄壞文件，只是改到錯的東西——而且每一步都能復原、先預覽再接受。
- 只有「把旁白改短／改長」這種**真的要寫字**的事才請模型自由寫一段字（`rewrite`），其餘都不用。

## 流程
1. 各編輯器原本的程式白話（`parseCommands`）先吃掉它讀得懂的句子。
2. 剩下的句子，**離線模式開著**時走 `_edOfflineTry`：引擎逐句判斷，輸出動作；有動作就直接回，沒有才退回原本的「請模型寫 JSON」。
3. 引擎的意圖表是資料（每個編輯器一張，`drawIntents`／`sceneIntents`／`deckIntents`／`gameIntents` ＋共用的 `commonIntents`：刪、隱藏／顯示、鎖定／解鎖、複製、改名），每個意圖有 `score`（關鍵字分數）、`needs`（要不要目標物件）、`build`（組動作）。分數差距 ≥ 2 程式直接決定；接近才問模型；全部 0 才問「全部意圖＋都不是」。
4. 同名的一群（`金幣 1`…`金幣 11`）一句「刪掉金幣」全部處理，不問；名字不同才問哪一個；遊戲裡有「原型」與「場景裡的實例」同名時，改數值找原型、刪除找實例（`adapter.prefer`）。

## 目前能做的（程式讀得懂）
| 編輯器 | 句型 |
|---|---|
| SVG／圖片 | 加形狀／文字（圓、方塊、三角、星、線、箭頭、多邊形；顏色、在某物件的右邊／上面…）、改顏色、改背景色、放大縮小（一倍、一半、大一點…）、往某方向移 N、旋轉 N 度、透明度、改文字內容、刪／藏／鎖／複製／改名 |
| 3D 場景 | 改顏色、改天空色、放大縮小、轉向 N 度、放到地上、刪／藏／鎖／複製（放東西與搬動原本程式就會） |
| 簡報 | 在第 N 頁／這頁後面加一頁講某主題、這頁加一個重點、轉場、語速、把旁白講短（請模型寫字）、改標題／旁白（引號）、刪／藏／鎖／複製頁 |
| 遊戲 | 角色跑快／慢、跳高、換背景音樂風格或關掉、改場景背景色、改遊戲名稱、刪／藏／鎖／複製東西（放東西原本程式就會） |

## 沒做、也不打算在程式層做
- 需要「創作」的句子（「畫一隻貓」「換一個比較緊張的劇情」）：這是模型的事；離線小模型做不好就是做不好，會明白說讀不懂，不假裝做了。
- 離線小模型回答字母題的**準確度**還沒用真的小模型量過（只用假模型測過流程與預設退路）。
