# 擴展回合（extend_rounds）：回合用完但事情沒做完，由使用者決定要不要繼續

問題：領域子Agent 的回合數固定（預設 20，技能包 40，簡報 90）。讀 wiki 這類長來源，讀完大綱才發現還有很多頁，回合用完就只丟一段進度回報，工作沒做完也沒有選擇。

## 行為
- **模型先評估**：子Agent 知道任務比預算大時呼叫 `extend_rounds({estimate, reason})`（只在子Agent 的工具清單裡，不進 `this.tools`）。系統提示裡有「回合預算」段：讀取最多用掉約 60%，其餘留給整理結果。
- **回合用完還在做**：程式代替模型提出同一個請求（`by: 'program'`），不再默默結束。
- **兩條路都停在同一張卡片**（`askCard`，單選）：允許 +N／改成其他數字（文字框）／不要：用現有的結果回答／以後都不要問（自動擴展到總回合上限，文字框可填上限，預設 60）。
- **誠實失敗**：選「不要」、取消卡片、或總上限用完，回傳「【這個請求沒有完成：原因】」＋進度回報（做了什麼、卡在哪、建議縮小需求），並帶 `exhausted:true, extendFailed:'denied|cap|asks'`。不會再問第二次。
- 擴展後從原來的回合接著做（`maxRounds += N`，迴圈不歸零）。

## 保護
- 估計值限制在 4～60；使用者回的數字由程式重新限制（不是數字＝當不要）；ask 模式絕對上限 200 回合；auto 模式用「總回合上限」（10～200）擋。
- 每個子任務最多問 4 次（ask 模式）。
- 批次平行的子任務（`rateLimitPerMinute` 有值）不問、也不給這個工具（沒有可以停下來等的使用者）；協調者（mixer）也不問。
- 根對話目前沒有固定回合上限（靠重複呼叫攔截等機制），所以這個機制只管子Agent。

## 設定
`advancedSettings.roundExtend = { mode: 'ask'|'auto', cap }`。斜線指令 `/rounds`（看）、`/rounds auto 60`、`/rounds ask`。

## 測試
`scripts/eval/extend-rounds.eval.js`（真實 Electron、假 LLM）：卡片規格合法、不要＝誠實失敗只問一次、允許後接著做完、改數字、亂寫數字當不要、以後都不要問→存成 auto 並之後不再放卡片、用光上限失敗、auto 在上限內完成不問、模型自己呼叫 `extend_rounds` 走同一張卡、批次不問、取消當不要。卡片在真實頁面上渲染過（四個選項、兩個文字框、送出／取消）。

# 工具送法二選一：原生 schema 或文字清單，由模型卡決定
工具清單只送一種：原生 tools 參數，或系統提示裡的文字清單（`[PREDEFINED TOOLS]`＋`[CALL:...]` 慣例），不兩份都送（原生模式本來就不產生文字清單）。`toolCallMode` 為 `auto` 時：
1. 先看端點／模型是否支援原生（探測快取＞內建表＞模型名稱）；不支援就用文字。
2. 支援時看模型卡（`/benchmark-model`）：基準測試現在會對支援原生的模型，用文字清單再測一次「單一工具呼叫」，兩個分數都記進卡片（`toolMode`、`test2TextScore`）。原生分數 < 50 且文字清單高 15 分以上，才記 `toolMode: 'text'`，之後自動模式改用文字清單；其他情況維持原生（省 token）。卡片的端點必須跟目前端點相同才生效。
