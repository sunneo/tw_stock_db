# 離線日誌格式學習（log_learn／log_ask）

給一份沒看過格式的文字日誌，程式自己找出格式、存進離線訓練器，之後可以摘要與問答。**全部是程式計算，不呼叫模型。**

## 流程（`renderer/src/logmine/log_core.js`，純函式）

1. **認格式**：確認是文字（控制字元與無法解碼字元的比例；二進位直接拒絕）；看每行是不是 JSON、有幾個 `key=value`、開頭有沒有時間戳、有沒有等級詞、有沒有堆疊續行 → `json_lines`／`key_value`／`timestamped`／`free_text`。
2. **多行紀錄**：沒有時間戳開頭的行、堆疊追蹤（`at …`、`Caused by`、Python Traceback）接到上一筆，不算獨立紀錄；順便統計例外類別。
3. **遮蔽已知型別**：時間（ISO、syslog、nginx）、URL、UUID、IP（含 port）、MAC、十六進位、路徑、耗時、大小、數字 → `<TS>`、`<IP>`…，並記下原始值。
4. **試多種分詞**：空白、空白＋標點（`[]()=:,;|"'` 各自成詞）。
5. **分群（Drain 風格）**：先依詞數分桶，桶內比相似度（預設 0.5），同一群裡不同的位置變成 `<*>` 欄位；JSON 每行一筆則以 `message` 欄位當內容、`time`／`level` 當標頭。
6. **挑最好的分詞**：分數＝涵蓋率（重複的行佔多少）＋模板越少越好＋不能全是 `<*>`。涵蓋率低於 30% 標成「弱」，不假裝學會了。
7. **統計**：每個模板的次數、等級、第一次／最後一次（行號與時間）、欄位型別與值分布（前 5 名、數字的最小／最大／平均）、尖峰分鐘。
8. **摘要與問答**：全是查詢——摘要、最多、第一次／最後一次、數量、欄位分布、最忙時段、模板列表、找某個值（需要原始行）。**開放式問題不亂答**，回傳 `kind:"open"` 與精簡脈絡（模板＋統計，不是整份日誌）給呼叫的模型。
9. **比對新紀錄**：`matchLine` 同樣遮蔽、分詞後比模板，取出欄位值；比不到就說比不到。

## 存進離線訓練器

領域 `log_formats`，一個格式一條規則：觸發是「貼上的文字像這個格式」（模板轉成的正規表示式，最多 25 個）、附上精簡模型（模板、欄位、統計；**不含整份日誌**，約 3 KB／格式）。貼上同格式的一行，訓練器直接呼叫 `log_ask`，回答「這行屬於哪個模板、欄位值、這種紀錄的統計」。無關的句子不會被這條規則命中。

## 工具

- `log_learn`：`text`／`file_id`／`path`（桌面版）三選一；預設放一張**互動卡片**讓使用者看格式摘要、改名稱、選存或不存（`confirm:false` 略過）。
- `log_ask`：`question`、`format`（省略＝最近一份）或直接帶日誌；單行 `text`＝問「這一行是什麼」。
- 都在 research 與 coding domain，不佔根層級 context。

## 限制

- 模板好不好只能靠一致性判斷（涵蓋率、模板數、通配比例），沒有「標準答案」。
- 多行紀錄只處理「續行接上一筆」；混合格式的檔案會學出多種模板，但不會自動切成多種格式。
- 欄位型別靠規則判斷；沒涵蓋的當成文字。
- 預設最多分析 5 萬行（可調到 20 萬），超過會註明只分析了前面。
- 只存模板與統計，所以「找某個值在哪幾行」只有同一個對話裡剛學過、或重新提供檔案時才能答。

## 測試

`node renderer/src/logmine/log_core.test.js`：帶堆疊的應用程式日誌、syslog、nginx、key=value、JSON 每行一筆、二進位／太短／幾乎沒有重複、三萬行效能；問答、比對、訓練器規則（命中格式、不誤判無關句子）、存檔後還原。真實 App 驗證：卡片確認 → 存進訓練器 → 重新整理 → 從訓練器問答 → 貼上一行被規則命中。

# 設定檔與「從文字自己長出文法」

三種輸入，三條路（`log_learn` 自動判斷，也可用 `kind` 指定）：

| 輸入 | 模組 | 做法 |
|---|---|---|
| 重複句型的日誌 | `log_core.js`（FaLog） | 模板探勘：遮蔽型別、分詞、分群、欄位統計 |
| 章節式設定檔（INI、TOML、EDK2 INF／DEC／DSC／FDF、.env） | `cfg_core.js`（FaCfg） | 章節→條目解析、型別、重複鍵、空值、比較；EDK2 的 Sources／PCD／LibraryClasses／!include／DEFINE |
| 其他行導向格式（YAML、BitBake、nginx、Dockerfile、Makefile、自創格式） | `gram_core.js`（FaGram） | **讀過後自己建規則、用全文驗證、吃不掉的再長出新規則** |

機密（密碼、金鑰、token、網址裡的帳密）在 FaCfg 與 FaGram 的存檔、問答、給模型的脈絡一律遮蔽。

## FaGram：文法從輸入長出來

流程：**讀 → 建規則 → 驗證 → 再長**。

1. **讀（帰納）**：從文字統計出
   - 賦值的運算子（`=`、`:=`、`?=`、`??=`、`+=`、`:`、`=>`…；不是事先列好，是最左邊、在字串與 `${}` 之外、夾在鍵與值之間的符號串）
   - 鍵名的修飾（`:append`、`:qemux86-64`；`_append` 這類字尾要在 ≥2 個不同名稱出現才算）
   - 行首關鍵字（`inherit`、`FROM`、`listen`；規則見下）、清單記號、指令記號（`!include`）、區段標題、函式（`name() { }`，本體當原文）
   - 註解記號、續行（行尾 `\`）、引號、`$` 引用
   - 區塊靠縮排還是大括號
2. **建規則**：以上存成一份「文法」資料（可存進離線訓練器、可輸出 EBNF 或 ANTLR 風格的文字）。
3. **驗證**：用文法解析全文，涵蓋率＝被某條規則吃掉的陳述佔多少。吃不掉的列出來。
4. **再長**：用吃不掉的陳述提出新規則（它們共有的行首符號可能是註解／指令／清單、共有的行首單字可能是關鍵字、沒見過的運算子），**每個提案都用全文重新驗證，涵蓋率要上升、而且原本吃得掉的一個都不能壞**才採用，每一輪記在 `trail`（加了什麼、涵蓋率從多少到多少）。
5. **邊讀邊學**：`extend()` 讀新樣本，只補文法裡沒有的規則。

防止作弊與誤判：
- 「把吃不掉的行全宣告成註解」被擋：註解提案至少要有 2 行共用同一個記號，被吃成註解的行不能超過全部陳述的一半，而且標成「較弱的推測」。
- 關鍵字：出現 ≥2 次，或全大寫（`FROM`），或全小寫且這份格式已有別的結構（運算子、大括號、區段、清單）佐證；一般英文散文不會被學成關鍵字。
- 日誌（大量以時間開頭）、二進位、散文、太短都明確拒絕。

## 限制（老實說）

- **這不是通用的文法學習**：只看例句，沒辦法學出正確的文脈自由文法（理論上做不到）。這裡只涵蓋「行導向、有鍵值或關鍵字、用縮排或括號分區塊」這一族，不是 LALR 表生成；輸出的 EBNF／ANTLR 是給人讀、給 ANTLR 當起點的描述，不保證能直接當完整的語言文法使用（縮排需要自己加 INDENT／DEDENT）。
- 起點有少量先驗：註解記號的候選（`#`、`//`、`;`、`--`）與運算子字元集（`=:?+.!<>~&|`）；不在裡面的（例如 `%%`）靠「再長」那一步從吃不掉的行提出並驗證。
- YAML 只處理映射、清單、`#` 註解；多行字串、錨點與別名（`&`、`*`、`<<`）不展開。
- BitBake 只列出每個操作與順序，**不計算變數最後的值**（那需要完整的 BitBake 展開）。
- 函式本體當原文，不解析裡面的 shell 或 Python。
