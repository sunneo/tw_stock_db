# 混合內容理解：自學習的語法高亮＋英文句子與意圖

一份輸入裡夾著英文敘述、PHP、HTML、JavaScript、WebGL 著色器（GLSL）、TOML、INI、Python、CSS、JSON、YAML、shell、SQL、錯誤輸出…，**不用事先標記**：切段、認語言、逐詞著色，並從英文句子推出「要做什麼、對什麼、引用哪一段」，對上離線訓練器的意圖。

## 兩個模組（純函式，不呼叫模型）

### FaMix（`renderer/src/logmine/mix_core.js`）：切段、認語言、著色
1. **明確記號**（信心最高）：圍欄（帶語言名稱）、`<?php … ?>`、`<script>`（`type="x-shader/x-fragment"` 就是 GLSL）、`<style>`、heredoc（標籤是 SQL 就是 SQL）、文件開頭的 `---`。沒有 `?>` 結尾的 PHP 檔不當明確區段（會吃掉後面的散文）。
2. **其餘的行逐行評分＋Viterbi**：每行對每種語言算分數（符號、關鍵字、結構形狀），切換語言要付代價，所以單獨一行沒把握時沿用前後文（前後都是 JS，這行就是 JS）。分數都很低的標「不確定」。區段信心度＝這段各行分數的 softmax 機率，並列出次佳的語言。
3. **自學習**：區段定下來後，把「這個語言的區段裡常出現、別處沒有」的識別字學成該語言的詞（`uTint`、`uPulse` 之類），再評分一輪；學到的詞存進設定（`mixLearned`），下次沿用。
4. **逐詞著色**：每個語言有自己的詞彙層（註解、字串、數字、關鍵字、型別、內建函式、函式名、變數、標籤、屬性、區段、鍵…）；散文裡的行內程式（反引號、路徑、駝峰識別字）也標出來。
5. 輸出 HTML（暗色、每段有語言標籤、信心度、行號、內容跳脫）。

### FaNlu（`nlu_core.js`）：英文句子→框架→意圖
1. **詞類標註**：封閉類別（冠詞、介系詞、代名詞、助動詞…）查表；動詞／名詞靠詞表、後綴、前後文（`the test failed` 的 test 是名詞，`Test the page` 是動詞）；行內程式是 CODE，不拿去判斷動詞。
2. **片語切分**：名詞片語、動詞片語（含小品詞 `speed up`、`to` 不定詞）、只有助動詞的片語（AV）、介系詞片語。
3. **子句文法 + LALR 分析表**（用前面做的 FaLR）：祈使句、問句（how／why／what／where、倒裝）、請求（can you…）、「我想要…」、陳述句；每條產生式帶角色（動作、對象、主詞、介系詞片語）。解析不了的句子，把它的片語序列**學成新的子句骨架**後重新驗證（同「讀→建規則→驗證」）；還是不行就保留原句、標低信心。
4. **框架**：`{ 類型, 動作, 對象, 修飾, 介系詞片語, 疑問詞, 否定, 引用的程式 }`；包裝說法（`I want to X`、`Could you X`、`would you mind X-ing`）取出真正的動作；被動（`the config is loaded`）的主詞是被作用的對象；問句分成診斷（why）、做法（how）、解釋（what）、位置（where）。
5. **意圖**：訓練器每條規則的意圖說明與例句用同一套管線分析一次（動詞同義群、名詞、對應的語言），框架對它們打分並附證據；**只有動作對上、沒有對象或語言佐證的不算數**。
6. **混合內容**：句子裡的「this shader」「the query below」「the error above」「the settings file:」對回最近的、類型相符的區段（shader→GLSL、query→SQL、config／settings→TOML／INI／YAML／JSON、error→錯誤輸出…）；冒號結尾或 below／following 指向後面的區段。

## 工具與 App

- `mix_understand`：切段＋句子框架＋引用＋意圖。
- `mix_highlight`：切段＋著色，產生 HTML 下載附件。**附件卡片上多一顆「🪟 檢視器」**（所有 `.html` 附件都有），開一個跳出的浮動視窗（概念同 aidoc、設計檢視器）：內容在沙盒 iframe（`allow-scripts`，碰不到助理頁面）、可拖曳、縮放、最大化、用瀏覽器分頁開啟、下載；同一份只開一個。`open:true` 直接開。
- 訓練器的試跑（`_otDryRun`）多一個 `nlu` 欄位：沒有規則命中時看得出「要做什麼、對什麼、引用哪一段」。

## 準確度（老實報）

- **逐行語言識別**：兩份各 50 多行、七八種語言混在一起的無標記文件，逐行準確率 100%；第二份是調整特徵時沒用過的，只修了一個結構問題（無 `?>` 的 PHP）。這兩份是我自己寫的，不代表所有真實文件。
- **句子框架**：每一組新句子第一次量到的準確率是 **50%、75%、65%、75%**（動作、對象、類型都對才算）；每次把錯的原因歸納成通用規則（小品詞、多個限定詞、複數名詞、副詞可省略、被動、動名詞、AV 與祈使句分開、並列動作、關係子句…）後才有現在的數字。**對沒看過的新句子，預期在 65–75% 左右**，不是 100%。
- **意圖比對**：目前只是動詞同義群加名詞重疊，沒有語意向量；訓練器的規則目錄裡意圖說明很短時，分數會偏低。

## 限制

- 只做英文。語意只到「動作和對象」，不做推理；長句、嵌套子句、省略、反諷會錯，解析不了就保留原句與低信心。
- 很短的片段分不出語言（`x = y + 1` 在 JS、PHP、Python 都成立）：靠前後文與信心度；單獨一行沒有前後文時信心不高。
- TOML 與 INI 很像時（`[server]` 加 `key = "value"`）信心會偏低，並列出次佳語言。
- 巢狀嵌入（PHP 在 JS 字串裡、JS 在 HTML 屬性裡）只做單層；`<script>` 的開頭與結尾標籤行目前會獨立成 HTML 區段。
- 新語言（沒有內建特徵）分不出名字，只會是低信心或不確定。
