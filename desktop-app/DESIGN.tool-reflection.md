# 工具呼叫的反思：「我沒有這個工具」要先查，動作明確的需求程式直接做

> 範圍：2026-10-17 的「語音事件」之後做的整組機制：命令直接做、鬆散說法補工具、宣稱偵測＋全領域搜尋＋退回、別名（程式端、不佔 context）。
> 這是[反思總覽](DESIGN.reflection.md)的第 3 種。細節與驗證數字在 [DESIGN.unit-catalog.md 第三十五節](DESIGN.unit-catalog.md)；中英互譯在第三十六節；全貌在 [DESIGN.colu.md](DESIGN.colu.md) 第七節。

---

## 一、事件（為什麼做）

使用者說「用英文語音說 Goodnight sleepy head」。模型（`nemotron-3-ultra`）回「我沒有語音合成工具」，建議自己用別的服務；使用者糾正「你有 TTS，它不是 skill」後重來，結果還是不對，最後使用者自己用 `/media-text-to-speech` 才成功。

原因：`text_to_speech` 在「影音處理」領域，最上層的工具清單沒有列；模型說沒有之前**完全沒有反思**「別的領域會不會有」。

## 二、三層修正（都是程式）

```
使用者說的話
   │
   ├─ ① 動作明確 ──→ 程式直接做（不經過模型，念的字一個字都不改）
   │
   ├─ ② 鬆散的說法 ─→ 最上層直接拿到專用工具＋一段做法提醒（FA_TASK_TOOL_HINTS）
   │
   └─ ③ 模型回「我沒有某某工具」
          ▼
      偵測宣稱 → 取出它在找的概念 → 搜尋「所有領域的所有工具」→ 找到就退回請它用
          ▼
      沒找到 → 不打擾（讓模型說沒有）→ 之後可走達成路線（plan_route）
```

### ① 動作明確 → 程式直接做

- **語音**（`tools/tts_intent.js`，48 項測試）：「用英文語音說 xxx」「請用語音念：xxx」「把「xxx」念出來」「朗讀 xxx」「tts: xxx」「read aloud: xxx」→ 走 `/media-text-to-speech` 同一條路，畫面上放使用者原本那句話。
  **不當成命令的**（交給模型）：提問（怎麼用語音合成？你有語音功能嗎）、單純的「說明一下…」「念書」「讀一下檔案」、只剩功能名稱、有附件、離線模式。
- **中英互譯**（`tools/translate_core.js`，87 項測試；`translate_text`、`/translate`、自然語言命令）：同樣「程式認得就直接做」。離線翻譯模型（OPUS-MT）、版本釘死放在 `vendor-models` 分支、程式檢查譯文（佔位符保護、簡繁、標點）、線上模型→重來→離線備援；下載前一定先問（約 118MB）。
- **寫新命令的規則**：仿 `tts_intent.js` 寫 `parse(message)`；**一定要寫「不能誤判」的反例測試**；在 `_submitChatInput` 接上，走該命令原本的處理函式。

### ② 鬆散的說法 → 最上層拿到專用工具

`FA_TASK_TOOL_HINTS` 每筆有 `re`（觸發）、`neg`（排除提問與別的意思）、`tools`、`note`。偵測到語音／朗讀／念出來／TTS（排除語音辨識、逐字稿、怎麼用／設定）→ 最上層會看到 `text_to_speech`，並附一段做法提醒：text 原樣、voice 留空、它是工具不是 skill。

### ③ 模型說「我沒有某某工具」→ 程式替它反思（`tools/cap_reflect.js`，45 項測試）

- **宣稱偵測**：看回覆開頭的 320 字（中英文），取出它在找的概念詞（「沒有〔語音合成〕的工具」中間那段）。
- **搜尋所有領域的所有工具**：CJK 雙字詞＋英文字，依稀有度（idf）加權。權重：工具名稱 2.5、別名 1.6、說明 1、領域標籤 0.4。最低 5 分，且不低於最高分的一半——**寧可漏掉也不亂提醒**。
- **退回提醒**（約 450 字）：列出 1～3 個工具、所在領域、怎麼用（最上層有就直接呼叫；沒有就 `delegate_to_subagent` 指定領域），要求原樣用使用者的字；都不符合才可以說沒有，並說明查過哪些。
- **上限**：每一輪最多 2 次；這一輪已經委派過、查過工具細節（`delegate_to_subagent`、`get_tool_details`、`catalog_query`）就不再提醒。
- **觸發點**：宿主的 `_noToolClaimNudge(text, counterHolder)`，在模型回覆結束時呼叫。

## 三、別名：只在反思時用，不佔 context

- **放哪**：程式端的查詢表，只有 `cap_reflect.search` 搜尋時讀；**不放進系統提示、不放進工具說明、不傳給模型**。實測系統提示長度不變。
- **什麼時候才花 context**：只有「模型說沒有工具」而且搜尋命中時，才多一則約 450 字的退回提醒；沒觸發是 0。
- **兩個來源**：
  1. **內建口語別名**（`SEED_ALIASES`，25 個常用工具）：寫的是使用者平常怎麼說這件事（念出來、畫畫、做簡報、PDF 接起來），不是工具說明裡的字。
  2. **學來的別名**：反思退回提醒之後，模型的下一個最終回覆不再說「沒有工具」＝成功，就把使用者那句話記成第一名工具的別名（每個工具最多 3 句、最多 400 個工具，存在 `tool-aliases.json`）。提醒了兩次它還是說沒有，就不學。`/tool-aliases` 看、`/tool-aliases clear` 清。
- **為什麼只學第一名一個工具、每個最多 3 句、可清除**：「不再說沒有」不等於它真的用了那個工具；學錯了要能清。

## 四、驗證（真實工具清單 215 個）

- 語音：「用英文語音說Goodnight sleepy head」→ 合成的文字就是 `Goodnight sleepy head`，模型呼叫 0 次；「把「晚安，好夢」念出來」→ `晚安，好夢`；「怎麼用語音合成？」→ 交給模型。
- 反思：說沒有語音工具 → 找到 `text_to_speech`（領域 `media_av`）；沒有 PDF 工具 → `images_to_pdf`；沒有影片轉 gif → `convert_to_animated_gif`；真的沒有對應工具的需求（寄信、股價、量子、翻譯）→ 不打擾。
- 抓到並修掉的錯：某些領域的 `toolNames` 是函式（動態），直接當陣列走訪會丟錯被吞掉，反思永遠回空——走訪前要先判斷是函式還是陣列。

## 五、跟達成路線的關係

工具反思找不到對應工具 ≠ 做不到。找不到之後的下一步是[達成路線](DESIGN.reflection.md)（`plan_route`）：判斷能不能用現成模型、寫程式、UML 設計做出來；需要外部世界的（寄信、發文、付款）給 API／瀏覽器控制／範本三條路，**副作用一律先問**。
目前還沒自動銜接：`catalog_discover` 的輸出會標出缺口屬於哪一類並提示用 `plan_route`，但「模型說沒有工具、搜尋也沒找到」那條路只是不打擾。

## 六、限制

1. 搜尋是字面比對。「畫一隻貓」只靠「繪圖」命中、工具說明寫的是「畫 SVG」，分數不夠就不提醒。門檻優先求不打擾。
2. 宣稱偵測只看回覆開頭 320 字；模型先做了一堆事、很後面才說沒有，不會觸發。
3. 語音命令辨識是句型比對，沒涵蓋的說法落到第 ②、③ 層。
4. 學來的是整句話，換個說法就搜不到。
5. 種子別名要人工維護（25 個）；其他工具靠學。

## 七、要改的時候

| 想做的事 | 改哪裡 |
|---|---|
| 新增工具的口語別名 | `tools/cap_reflect.js` 的 `SEED_ALIASES`，再跑 `node renderer/src/tools/cap_reflect.test.js` |
| 新增「動作明確就直接做」的命令 | 仿 `tts_intent.js`，加測試（含反例），在 `_submitChatInput` 接上 |
| 給鬆散說法補專用工具 | `FA_TASK_TOOL_HINTS` 加一筆 |
| 調整搜尋門檻 | `cap_reflect.js` 的 `minScore`（5）與「不低於最高分一半」 |

## 八、移植（搬到別的專案）

`cap_reflect.js`、`tts_intent.js` 都是純函式、沒有相依，原樣複製即可。宿主要做的只有兩件事：
1. 提供**工具清單**（名稱、領域、說明、這個工具是不是在最上層）給 `search`；
2. 在模型回覆結束時呼叫宣稱偵測，命中就把退回提醒當系統訊息插回對話，再讓模型重來一次。
把你自己的工具的口語叫法補進 `SEED_ALIASES`（例如 Redmine：「報工」「登時數」→ time_entries）。詳見 [DESIGN.colu-porting.md](DESIGN.colu-porting.md)。

## 九、決策紀錄

- **別名放程式端，不放提示**：提示每輪都重送，別名只在反思時才需要。
- **寧可漏掉也不亂提醒**：誤報會讓使用者與模型都學會忽略提醒。
- **動作明確的需求不給模型**：念的字一個字都不能被改；省一次呼叫也省一次出錯。
- **只學第一名一個工具**：反思成功的判斷（不再說沒有）不精確，不要放大錯誤。
