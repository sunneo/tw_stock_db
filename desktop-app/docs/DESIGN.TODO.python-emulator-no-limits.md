- 「我希望python emulator裡面不要code example有被限制待遇」

- 「一樣要真正不設限  我要做到的是python裡面的環境人寫，ai寫都可以自由發揮」

## 原則
人寫或 AI 寫的 Python 程式，正常創作不該撞到固定上限；範例程式也不該為了遷就上限寫繞法。保護機制要「量測後自適應」或「明確失敗」，不能是一個小的寫死數字。

## 已做（2026-11-19，已提交、尚未發布）
- 圖片不設大小上限（大圖分段傳送）；`pick_file` 預設不限大小；編輯器文字與一般文字上限提高到 5000 萬字元。
- 畫布每幀指令不再是 200：上限十萬，視窗依實測「每道指令花多久」自適應，大幀每次螢幕更新最多畫一次最新的。
- 視窗數、節點數、清單項目、巢狀深度、畫布大小、圖片張數、WebGL 緩衝與指令數等固定上限全部大幅提高（`gui_bridge.js` 開頭常數）。
- 單一訊息上限 64 MB（只是擋失控）。

## 還沒做
1. **自帶 IndexedDB 當交換空間**：模擬環境的大資料（大圖、大檔、編輯器全文、檔案系統內容）超過記憶體預算時，換出到 IndexedDB，需要時再換回；程式端看不到差別。要先決定：換出的單位（分頁或整個物件）、預算怎麼自適應（依裝置記憶體與實測）、網頁版與桌面版共用同一層。
2. **真正不設限的傳輸**：目前單訊息 64 MB 仍是天花板。編輯器文字、文件區塊、WebGL 緩衝要比照圖片做分段傳送，之後可搭配上面的交換空間，不必整份常駐記憶體。
3. **整個模擬環境的上限盤點**：不只 GUI。檔案系統、網路、資料庫、執行時間、輸出行數等，逐項找出固定上限，改成自適應或明確失敗。
4. 驗證：真桌面版跑大圖（數十 MB）、十萬指令畫布、5000 萬字元編輯器，量測記憶體與是否卡住。
